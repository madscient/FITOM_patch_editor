# 実装状況

いま何が済んでいて、何が残っているか。セッション開始時はこのファイルを
読めば足りる。構成と規約は `docs/ARCHITECTURE.md`、判断の理由は
`docs/DECISIONS.md`(D-番号の引き方もそこ)。古い進捗ログは
`docs/history/STATUS-archive.md` にあるので、必要なときだけ検索して読む。

## このファイルの運用

- **進捗ログは直近5件だけ置く。** 追記して6件以上になったら、古い順に
  `docs/history/STATUS-archive.md` の末尾へ原文のまま移す。
- **利用者の確認待ちは下の「利用者の確認待ち」に集める。** 進捗ログに
  「目視確認は利用者待ち」と書くときは、同じコミットでこの一覧にも項目を
  足す。ログにだけ書くと、ログがアーカイブへ移ったときに見えなくなる。
- 利用者から確認結果の報告を受けたら、該当項目を一覧から消し、結果を
  進捗ログに書く。問題があった項目は修正作業として扱う。
- 項目の番号(V-xx など)は報告で使うので、振り直さない。消した番号は
  欠番のままにする。

## 現状の要約

- **データモデル層(`fpe_data`)**: プロファイル・全バンク種別の読み書き、
  CRUD、変更したファイルだけを書く保存(D-042)、共有バンクセット(D-041)。
  チップ別のパラメータ定義は `spec/chip-capabilities.json`(FITOM_X からの
  同期コピー)を `fpe::ChipCapabilities` 経由で読む(D-057)。VoicePatchType は
  FITOM_X の `FITOMdefine.h` に追従済み(D-058)。
- **GUI**: プロファイル選択 → アウトライン → バンク詳細 → 各編集画面
  (デバイス/レイヤード/パフォーマンス/ドラムキット・ドラムノート)。
  パッチピッカーは Category → Bank → Program(D-043)、クリックで試聴・
  ダブルクリックで確定(D-054)。キオスクモード(D-026/D-039/D-040)。
  試聴は FITOM_X 内部パイプ優先、未接続時は RtMidi(D-015/D-018)。
- **テスト**: `ctest` のスモークテスト1本(360項目、2026-10-23 時点)。
  GUI はテストしていない。GUI の確認は利用者が行う(`CLAUDE.md`)。

## 未検証(手元では確かめられないもの)

- `MidiPipeClient` の POSIX(UNIX ドメインソケット)経路。
- Linux/macOS での日本語フォントの候補パス(`loadFonts()`)。
- DSG の名前解決は、DSG を指す実データが `FITOM_staging` に無いため、
  テストとソースの突き合わせでしか確認していない(D-053)。
- スモークテストでの MSVC Debug CRT ダイアログの抑止(D-058)。
- 全体ビルドで出る MSB8028 は、同じビルドツリーを2つのパス(片方が
  ジャンクション)から build したためと見ている。中間ディレクトリに tlog の
  フォルダが2つあり、CMakeCache のソースとビルドのパスが別の経路になっている。
  確かめるには、古い方の tlog フォルダを消して警告が消えるかを見る(ビルド
  ディレクトリ内の削除なので、利用者の了解を得てから)。コードの変更とは
  関係しない。
- 2026-10-03 の履歴書き換え後、作業したクローン以外のマシンが新しい
  履歴に合わせてあるか、クローンごとの identity 設定が済んでいるか。
  合わせ方: `git pull` はせず、`git fetch origin` → 未 push のコミットが
  無いことを確認 → `git reset --hard origin/main`。未 push のコミットが
  あれば、それだけを新しい `origin/main` の上に `git cherry-pick` する。
  identity は `CLAUDE.md` のルール 6。経緯は
  `docs/history/STATUS-archive.md` の 2026-10-03 のログ。

## 未実装・未解決の課題

- バンク/パッチ(ドラムノート以外)の複製・削除 UI。`PatchWorkspace` の
  CRUD API はある。
- プロファイル自体の新規作成・削除 UI(メインメニューのボタンは表示だけ)。
- レイヤードパッチの ToneLayer 自体の追加・削除 UI(既存レイヤーの編集のみ)。
- "direct" ドラムキットの sw_bank/sw_prog 等の編集(D-038)。
- `*.sccwave.json` の内容のモデル化(参照の bank/file だけ読んでいる)。
- `PatchWorkspace::saveAs()` が、外部参照の `banks` / `bank_overrides` の
  ファイルをコピーしない(D-041)。
- パッチより下の階層にあるモデル化していないキーは、編集したファイルでは
  保存時に失われる(最上位のキーは D-061 で保持する)。FITOM_staging の実データ
  には該当するキーが無い(2026-10-23 に全プロファイルで確認)。
- `*.pcmbank.json` に `entries[]` を直接書く形(スキーマでは `entry_no` /
  `start_offset` / `end_offset`)を、エディタはスキーマの形で読み書きして
  いない(adpcm_packer の出力の形 `offset` / `size` で読む)。`entry_no` が
  連番でない場合の扱いも無い。実データはすべて `adpcm_json` 経由なので
  表面化していない。
- `builtin_swpatch_meta` バンクの sw_bank/sw_prog の編集 UI(D-050/D-053)。
- OPLL 系 ROM 音色専用の編集画面は無い(利用者の指示で保留中、D-022 の頃)。
- 新規作成したバンクは、FITOM_X 側の再起動まで認識されない(D-047。
  D-049 の後も残っている)。
- 同じファイルを指す2つのオブジェクトを両方とも編集すると、片方の変更が
  失われる(D-051。理論上の稀なケースで、実際に起きた記録は無い)。
- 仮想 MIDI コントローラ(未着手)。
- AWM サンプルゾーンパッチには編集画面が無い(バンク詳細での閲覧のみ)。
  PCM 波形バンクの中身は、利用者の方針で編集対象外(`PcmBank.h`)。
- プリファレンスの保存先は、Windows 以外では実行ファイルの場所を取得
  しておらず、カレントディレクトリになる(`Preferences.h`)。
- `hw_banks[]` に ADPCM 系の group を書いた場合の読み方が FITOM_X と違う
  (エディタは pcmbank として読み、FITOM_X は hwbank として読む。D-058)。
  実データはすべて `pcm_banks[]` 経由なので表面化していない。
